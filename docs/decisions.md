## 2026-10-19 · Day 1 scaffold

### D1 — Hyperdrive is free on Workers Free → use it

**Checked:** Cloudflare docs on 2026-10-19 — [Hyperdrive pricing](https://developers.cloudflare.com/hyperdrive/platform/pricing/), [Workers pricing](https://developers.cloudflare.com/workers/platform/pricing/#hyperdrive), [Hyperdrive FAQ](https://developers.cloudflare.com/hyperdrive/reference/faq/), [Hyperdrive limits](https://developers.cloudflare.com/hyperdrive/platform/limits/).

- "Hyperdrive is included in both the Free and Paid Workers plans." FAQ: "Is Hyperdrive available on the Workers Free plan? Yes."
- Free plan: **100,000 database queries/day** (reset 00:00 UTC; over the limit, queries error), **~20 origin connections per config**, 60 s max query duration. No egress charges.
- Our usage (one household-scale PWA, a handful of queries per page) is far below this.

**Decision:** Neon via **Hyperdrive**. `@neondatabase/serverless` is not used. Revisit only if we approach 100k queries/day.

### D2 — Drizzle driver is node-postgres (`pg`), not Postgres.js

Cloudflare's [Drizzle + Hyperdrive guide](https://developers.cloudflare.com/hyperdrive/examples/connect-to-postgres/postgres-drivers-and-libraries/drizzle-orm/) states: "Pairing Drizzle ORM with the Postgres.js driver over Hyperdrive is not currently supported. Switch your driver to node-postgres." We use `drizzle-orm/node-postgres` with a `pg.Client` per request (`connectDb`). Verified locally in workerd (`wrangler dev`) through the Hyperdrive binding's `localConnectionString`.

### D3 — Hyperdrive caching disabled for MVP

Hyperdrive caches read queries by default (60 s) and never invalidates on write. Session lookups and "tick then see it on My List" need read-after-write consistency. Create the staging config with `--caching-disabled`. If the catalogue later needs caching, add a second cached binding for Browse only (watch the ~20 origin-connection budget across configs).

### D4 — Formatter: Biome (format-only). Linter: Oxlint

Roadmap said pick oxfmt **or** Biome. oxfmt 0.73 skipped `.svelte` files entirely when tested; Biome 2.5 formats Svelte (`html.experimentalFullSupportEnabled`) and organises imports. Biome's linter is disabled so Oxlint is the only linter.

### D5 — TypeScript 6, not 7

TypeScript 7.0 (native) is out, but SvelteKit 3.1 and svelte-check 4.7 declare `typescript@^5 || ^6` peers and `svelte-kit sync` crashes under 7. Pinned `^6.0.3`; revisit when Kit supports 7.

### D6 — pnpm 12 with default `minimumReleaseAge`

`packageManager: pnpm@12.14.0`. pnpm 12 refuses packages published < 24 h ago by default; we keep that supply-chain guard (so a few deps resolve one patch behind "latest"). Build scripts allowed only for `esbuild` and `workerd` (`allowBuilds` in `pnpm-workspace.yaml`).

### D7 — SvelteKit 3 specifics

- No `event.platform`: bindings via `import { env, waitUntil } from 'cloudflare:workers'` (adapter-cloudflare 8).
- `#lib/*` Node subpath imports replace `$lib`; paths need extensions.
- `tsconfig` sets `checkJs: false` because the generated `worker-configuration.d.ts` imports the built `_worker.js`.
- `worker-configuration.d.ts` is gitignored and regenerated by `prepare`/`typecheck`/`build`: its content changes depending on whether a build output exists, so a committed copy + `wrangler types --check` can't be stable across local and CI.

### D8 — Four bottom tabs: Browse · My List · Tick · Season

Day-1 brief asks for bottom tabs for the four MVP screens. Roadmap §5 describes Tradition Tick as a Sheet/Drawer over Browse/My List. Both hold: the **Tick tab** is a quick "tick something off" entry point (search → panel), and the same panel opens from Browse/My List rows on Day 5.

### D9 — Schema

- Lean tables per roadmap §4: `media`, `watch_events`, `user_media_state` + Better Auth `user`/`session`/`account`/`verification` (field names verified against `getAuthTables()` in better-auth 1.7).
- `snake_case` columns via Drizzle `casing` (both runtime and drizzle-kit).
- Better Auth IDs are `text`; `media.id` / `watch_events.id` are `uuid` (V1 UUIDs preserved; clients can mint tick IDs offline).
- `watch_events_precision_check` enforces `exact ⇒ watched_at`, `year ⇒ watched_year`; mirrored by the Zod `tickInput` schema.
- **V1 repo was not readable** from this environment (404 — private). Schema is derived from the roadmap's V1 summary; re-check enum values (`holidayRelevance`, `datePrecision`, `source`) against V1 before the migration script (Day 3).

### D10 — Single festive theme

One "festive midnight" palette (`--midnight`, `--berry`, `--mint`, `--holly`, `--gold`, `--paper`) mapped onto shadcn semantic tokens. No light/dark toggle in MVP.

### D11 — Workers Free CPU budget (risk)

Workers Free allows 10 ms CPU per request. Google OAuth + Email OTP avoid password hashing, which is the usual Better Auth CPU hog. Watch CPU time in Workers Observability on staging (Day 2).

## 2026-10-19 · Day 2 auth + staging

### D12 — Better Auth wiring on Workers

- `createAuth(db, env)` (`src/lib/server/auth.ts`) builds Better Auth **per request**, sharing the request's Drizzle client. `hooks.server.ts` exposes lazy `locals.db()` / `locals.auth()`, so signed-out pages open no DB connection; the client is closed with `waitUntil` after the response.
- Routes: Better Auth handles `/api/auth/*`; `/sign-in` (Google + Email OTP form actions, no client auth library), `/sign-out`, `/api/health` (`select 1` through Hyperdrive).
- Server-side `auth.api.*` calls + the `sveltekitCookies` plugin set cookies through SvelteKit's `cookies`. Kit 3 needs `redirect(303, url, { external: [...] })` for the Google hop.
- `session.cookieCache` (5 min, signed). Page loads verify it with `getCookieCache` and only build Better Auth / hit the DB on a miss. Trade-off: a session revoked elsewhere stays readable for ≤5 min.
- OTPs: 6 digits, 10 min, stored hashed, 3 attempts (Better Auth default). Emails go through Resend's REST API with one `fetch` (no SDK).
- `BETTER_AUTH_URL` is a plain var per environment in `wrangler.jsonc`. Secrets are declared in `secrets.required` (typed by `wrangler types`; `wrangler deploy` refuses to create a new Worker without them, so the first deploy uses `wrangler secret bulk`).
- `EMAIL_FROM` is optional. Unset = Email OTP shows "not set up yet" and Google still works. The Resend key in agent secrets is send-only and `christmaswatchlist.co.uk` is **not** verified on that Resend account (verifying needs DNS records, so it waits for cutover). Staging's `EMAIL_FROM` is a Worker secret set outside this repo; Resend accepts it.

### D13 — CPU on Workers Free: measured, borderline on cold isolates

Measured with `wrangler tail` on staging (account is Workers **Free**; `cpuTime` per request):

| Path | Median | p90 | Max |
| --- | --- | --- | --- |
| `/` signed out | 5 ms | ~25 ms | ~55 ms |
| `/`, `/my-list` signed in (cookie cache) | 5 ms | ~27 ms | ~60 ms |
| `/api/auth/*` | ~10 ms | ~25 ms | ~30 ms |
| Google sign-in start (POST) | 40–100 ms | n/a | n/a (rare, once per sign-in) |

The spikes are first requests in a fresh isolate (lazy module evaluation + JIT); warm isolates are 1–5 ms. All ~400 sampled invocations finished `ok` — none `exceededCpu`. Cloudflare allows isolates to run over occasionally and terminates only Workers that are *consistently* over.

Mitigations in place: the Kit `init` hook warms Better Auth once per isolate during **startup** (1 s budget, not the request's 10 ms); cookie-cache session reads skip Better Auth entirely; no password hashing.

If `exceededCpu` (error 1102) shows up in Workers Observability during beta, the next levers are: prerender static shells, trim the bundle (3.5 MB uncompressed), or Workers Paid ($5/mo) — the last one needs Andrew's sign-off (free-tier rule).

## 2026-10-20 · Day 3 catalogue

### D14 — V1 catalogue enums match the V2 shelves

Checked the V1 repo `schema/index.ts` and `app/api/media/route.ts` (the signed-out guide).

- `holiday_relevance` canonical values are `christmas`, `adjacent`, `nonRelated`, or null. Legacy strings (`tradition`, `unrelated`, `setting`, `christmas_adjacent`) were a V1 data migration, not current values. V2's enum matches the canonical set. Browse imports only `christmas` and `adjacent`.
- `date_precision` is `exact | year | unknown`, same as V2. Not imported on Day 3 (catalogue only).
- V1 `watch_events.source` also has `onboarding`. V2's enum is `manual | import`. Left alone until watch history is in scope. Do not widen the enum without asking.
- Public rows are `approval_status = approved` and `hidden = false`. `visibility_status` of `hidden` or `deleted` is skipped. V1 ids are kept. `source_ids.tmdb` is required.

`scripts/migrate-from-v1.ts` is a dry-run until `DATABASE_URL_V1` is set. It sets the V1 session read-only and refuses to run when the two URLs match.

## 2026-10-20 · Day 4 My List

### D15 — My List is favourites, split by this season's ticks

`user_media_state.is_favourite` is the list. No new table or column. A title is **watched** this season when the user has an `exact` tick inside 1 Nov–31 Dec, or a `year` tick for that season's year. `unknown` ("don't remember") leaves it in **still to watch**.

Browse rows toggle the flag. The Tradition Tick panel stays on Day 5, so the Watched section only fills from ticks that already exist (later, the tick action, or an import). Signed-out My List asks you to sign in and does not open a database connection.
